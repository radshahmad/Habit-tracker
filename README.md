# Habit Tracker — Self-Improvement Dashboard

A modern, local-first habit tracker and self-improvement dashboard. No account,
no backend, no cloud sync — everything you track stays on your own device.

## Features

- **Dashboard** — customizable widgets (show/hide, reorder, resize, reset to default)
- **Today** — track today's habits with date navigation, a general daily note, and
  a Correction Mode for fixing a specific past day
- **Tracker** — a dense weekly grid on desktop, day-by-day cards on mobile
- **Statistics** — completion trends, habit comparisons, streaks, filterable by
  habit and date range
- **Reports** — monthly reports with previous-month comparison and PDF export
- **Habits** — four tracking types (Simple, Count, Duration, Quantity), categories,
  manual or automatic ordering, archive or delete-with-history
- **Settings** — theme (light/dark/system), one general daily reminder, data
  retention, JSON export/import, dashboard reset

## Tech stack

React + TypeScript + Vite, Tailwind CSS, IndexedDB via Dexie, Recharts, date-fns,
lucide-react, jsPDF (loaded on demand), vite-plugin-pwa.

## Getting started

```bash
npm install
npm run dev       # start the dev server
npm run build      # type-check and build for production (outputs to dist/)
npm run preview    # preview the production build locally
npm test           # run the unit tests (streaks, completion %, validation)
```

## Privacy & data model

All data lives in an IndexedDB database in your browser. Nothing is ever sent to
a server. The only way data leaves the device is the manual **Export** button in
Settings, which downloads a versioned JSON file you control.

Web and mobile builds each keep their own separate local database — there is no
sync between them. Use **Settings → Export/Import** to move data manually between
devices.

## Deploying for free

This is a static site — any static host works. For example, with GitHub Pages:

```bash
BASE_PATH=/your-repo-name/ npm run build
```

Then publish the `dist/` folder (e.g. via GitHub Actions or the `gh-pages`
branch). The app continues to work fully offline once installed, thanks to the
service worker generated by `vite-plugin-pwa`.

Netlify, Cloudflare Pages, and Vercel all work too — just point them at
`npm run build` and the `dist/` output directory, and you can leave `BASE_PATH`
unset (it defaults to `/`).

## Installing as a PWA

Visit the deployed site in a supporting browser (Chrome, Edge, or Android/iOS
Safari) and use "Install app" / "Add to Home Screen". Once installed, it works
offline.

## Mobile (Capacitor)

This codebase is Capacitor-ready. To package it as a native Android/iOS app:

```bash
npm install @capacitor/core @capacitor/cli
npx cap init "Habit Tracker" "com.yourname.habittracker" --web-dir=dist
npm run build
npx cap add android   # and/or: npx cap add ios
npx cap sync
npx cap open android  # opens Android Studio
```

The web app's IndexedDB data stays local to whichever shell it's running in —
the native app has its own separate database from the browser version, by
design (see Privacy above).

## Project structure

```
src/
├── components/   common UI, layout (sidebar/bottom nav), and per-page widgets
├── pages/        one folder per top-level route
├── db/           Dexie schema and seed data
├── services/     all business logic (habits, statistics, reports, export, notifications)
├── hooks/        reactive Dexie queries + small UI hooks
├── utils/        date/calculation/validation helpers, covered by unit tests
└── types/        shared TypeScript types
```

Business logic (streaks, completion %, goal math) lives only in `utils/` and
`services/`, never duplicated in components — see `src/utils/__tests__/` for
the test suite covering it.

## Known limitations (intentional scope)

- The daily reminder uses a local browser timer; it fires reliably while the
  app/tab is open, but this is not a push-notification system, so it may not
  fire if the app has been fully closed for a long time.
- The Tracker grid's day headers display the habit's *current* configuration
  label; the completion/miss status itself is always computed correctly
  against whichever target was in effect on that historical day.
- Capacitor packaging is wired up via the instructions above but hasn't been
  built into committed `android/`/`ios/` folders — run `npx cap add` locally
  once you're ready to ship to a device or app store.
